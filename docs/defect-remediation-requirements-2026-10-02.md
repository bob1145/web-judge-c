## 2. 目标、范围与角色

### 2.1 目标与非目标

1. 建立登录、创建、启动、编译、判题、进度、终态、回收的真实闭环。
2. 匿名不能进入实时通道，普通用户不能操作未授权任务，提交程序不能改可信结果。
3. 事件、输出、进程、认证状态、配额和进度缓存全部具有资源上界。
4. 统一普通比较，避免跨路径差异和错误 AC；保证实时、磁盘、清缓存及重启后统计一致。
5. 保持单实例、文件存储和现有框架，复用接口与结果状态，最小修复。

**非目标**：数据库/分布式调度改造、框架替换、历史任务自动重跑、SPJ 算法改写、依赖漏洞全库审计、未经验证的容器逃逸宣称。真实 mTLS 非首期必交功能，但不可继续用占位 Header 冒充。

### 2.2 角色与场景

| 角色 | 场景 | 边界 |
| --- | --- | --- |
| 匿名 | 登录与失败重试 | 不得读取任务或发布进度 |
| 普通用户 | 两模式登录、创建/启动/取消/查询 | HTTP/WS 同一身份与任务所有权规则 |
| 管理员 | 管理授权任务、审计 | 管理权限显式授予 |
| 运维 | 代理/HTTPS/Worker/预算配置与重启 | 错配失败关闭，不安全模式不自动回退 |
| supervisor/Worker | 编译执行、权威事件 | 与提交程序身份及写权限隔离 |
| 提交程序 | 读输入、输出、写临时文件 | 无权改控制文件和可信工具 |
| 测试/发布 | 回归、协议负例、资源测试 | 授权隔离环境执行并留证 |

## 3. 功能需求与验收

“必须”为发布要求，“建议/待确认”为产品决策。AC 对应后续测试包 T；不能用源码检查替代真实协议和部署验收。

### 3.1 认证安全

**RQ-A01 双模式登录（DEF-01，P1）**
- 服务端决定模式；账户模式显示用户名/密码，访问码模式显示访问码；客户端不能自行决定权限。
- AC-A01：两模式真实浏览器成功建立会话并站内跳转；401、429、断网分别显示认证、限流、网络错误，兼容访问码历史 HTTP 200 + success=false，不假报成功。（T-A01）

**RQ-A02 实时身份与授权（DEF-04、N1，P1）**
- WS/SockJS 握手、STOMP CONNECT 绑定服务端验证会话；Origin、UUID、MVC 拦截器均不替代认证。
- SUBSCRIBE 校验目的地白名单和 owner/admin；拒绝客户端向服务器进度主题 SEND，不信任客户端角色/结果。
- 登出、到期、撤权后已有连接不能继续订阅或接收受保护更新。
- AC-A02a（N1）：匿名/失效凭据/不允许 Origin 不能建立保护会话；覆盖 WS 及启用 SockJS 传输；匿名与已登录 SEND 都不能伪造广播。（T-A02）
- AC-A02b（DEF-04）：A 只能订阅自身任务，授权管理员可订阅；登出、到期、重订阅均拒绝越权。（T-A03）

**RQ-A03 来源与认证限流（DEF-09、DEF-10，P2）**
- 仅直连地址属于可信代理时解析转发头，否则忽略 XFF；统一多头/多跳解析。
- 账户级、来源级独立限流；两认证模式的全部失败/锁定状态有容量、主动过期和饱和保护。
- AC-A03a：直连轮换 XFF 不改变来源；可信/非可信代理及畸形链均有断言；账户换来源不能无限尝试。（T-A04）
- AC-A03b：随机账户/IP 不突破容量，闲置键主动过期；淘汰不能清除仍有效的来源总限流。（T-A05）

**RQ-A04 凭证、日志、Cookie（DEF-18、DEF-19、N3，P2）**
- 会话仅经 Cookie 或 X-Session-ID；查询参数 sessionId 在普通/管理/下载/实时入口均不能认证，不保留隐式回退。
- 日志、错误、跳转及新 URL 不输出完整会话；审计用不可逆指纹或独立关联 ID。
- 生产 Cookie 强制 Secure、HttpOnly、显式 SameSite；创建/删除 Path、Domain 一致；HTTP 例外仅限明确本地模式。
- AC-A04a：两种登录和异常日志无完整 token，仍可审计关联。（T-A06）
- AC-A04b：HTTPS 登录/登出属性正确；浏览器 HTTP 不带安全 Cookie；伪造协议头不能降级。（T-A07）
- AC-A04c：仅 URL 凭据访问全部保护入口失败，Cookie/Header 正例成功，页面不生成凭据 URL。（T-A08）

**RQ-A05 跳转与默认配置（DEF-20、N4，P2）**
- 已登录 GET、访问码/账户登录共享站内返回规则；绝对/协议相对 URL、反斜杠、控制字符、编码绕过均回安全页。
- 删除硬编码账号/弱默认码；无有效认证材料拒绝启动；trusted-local 默认回环监听。
- AC-A05a：三分支共享跳转向量，站外地址不进入 Location 或可执行响应目标。（T-A09）
- AC-A05b：旧默认码不可登录；缺材料启动失败且不泄密；默认不监听外网。（T-A10）

**RQ-A06 环境绑定与 CSRF（N6、N7，P3）**
- 环境变化明确记录/拒绝/重新认证策略；管理员强 IP/UA 校验建议待批准，不将仅告警描述为已阻断。
- Cookie 状态变更校验 CSRF token；显式 Header 客户端采用受控策略，不能因任意自定义 Header 而绕过。
- AC-A06a：管理员/普通用户同来源、IP/UA 变化、移动网络按批准策略断言；强校验模式不匹配拒绝。（T-A11）
- AC-A06b：跨站表单、缺失/错误 token 拒绝，合法页面成功；SameSite 非唯一防线，CORS 不开放任意来源携带凭据。（T-A12）

**RQ-A07 Worker 认证（DEF-23，P1）**
- 首期拒绝没有真实客户端 TLS 的 cert-only 配置；占位 X-Judge-Worker-Mtls Header 不构成认证。
- 生产 Remote Worker 强制 HTTPS、服务端证书/主机名验证及实际支持认证；失败不回退 direct/无认证。
- AC-A07：伪 cert-only、生产 HTTP、无效服务端证书、认证失败均拒绝，支持模式正例成功；未来 mTLS 启用前独立证明证书/私钥加载、无证书和错误证书被拒。（T-A13）

### 3.2 Runner 契约隔离

**RQ-R01 路径（DEF-02，P1）**
- 区分宿主和执行环境路径，优先任务根内相对路径；创建文件前拒绝绝对路径、穿越、链接逃逸。
- AC-R01：Linux/Windows 根路径不同仍能读源码判题；危险输入不创建根外目录；native/remote 按支持矩阵实测。（T-R01）

**RQ-R02 轮询终态（DEF-03，P1）**
- 区分空批次、执行存活、退出、权威终态；轮询有间隔、截止、取消检查；终态前不解除预算。
- 异常退出有界回收，不依靠 24 小时残留清理。
- AC-R02：“空→编译开始→空→结果→完成”正确；启动延迟、非零退出、退出无终态、取消/超时均断言；轮询次数受间隔限制。（T-R02）

**RQ-R03 双事件面（N2，P1）**
- 宿主元数据与 runner 事件独立通道/文件、单写者明确；runner 截断不破坏宿主历史。
- AC-R03：宿主预写至少四条事件后启动，历史完整且 runner 首事件不漏；截断/替换/半行不造成游标倒挂或误消费元数据。（T-R03）

**RQ-R04 控制面隔离（DEF-05，P1）**
- 提交程序与 supervisor 身份/权限隔离，仅移动同身份可写文件不合格；只开放必要输入读和独立工作区写。
- AC-R04：事件/描述/摘要/取消通道/可信工具篡改均失败，伪造 SUMMARY/COMPLETED 无效；正常编译及临时文件可用。（T-R04）

**RQ-R05 有界读事件（DEF-06，P1）**
- 字节偏移增量读取，单行/单批/累计量/字段有界；有限保留尾行，不全量加载。
- AC-R05：超长行、大量事件、分段 JSON、无换行、截断/替换受控；内存由配置上界决定。（T-R05）

**RQ-R06 输出与进程族（DEF-07、DEF-08，P1）**
- stdout/stderr 边读边计数，超限终止执行组并 OUTPUT_LIMIT_EXCEEDED，只留有界摘要；生成器同样受限。
- 父退出不能跳过后代清理，最终管道排空有截止。
- AC-R06a：小额度双流/混合输出超限稳定，supervisor 存活、缓冲有界。（T-R06）
- AC-R06b：父退出子持管道在执行截止加清理预算内结束，无残余进程/句柄，不污染下一用例。（T-R07）

### 3.3 普通比较

**RQ-C01 统一比较语义（DEF-11、DEF-12，P1）**
- 共享分词、空白/换行、编码、数值分类、精度及错误规则；precision 进入 runner 契约。
- 建议保留绝对误差意图：整数对整数任意精度精确比较，有限小数用十进制绝对误差；NaN/Inf 仅文本精确匹配。DEC-03 批准后冻结，不统一转 double。
- precision 有限且非负；数字长度/指数受控，非法参数明确拒绝；SPJ 不改变为普通比较。
- AC-C01：Java/Python/声明支持 Worker 的共享向量一致，覆盖重复空白、空输出、中文、科学计数法、零精度和误差边界。（T-C01）
- AC-C02：9007199254740992/9007199254740993 为 WA，NaN/5 为 WA；NaN/NaN、Inf 按批准契约断言；5.0000000001/5 在 1e-9 下各路径一致。（T-C02）

### 3.4 生命周期、配额、统计

**RQ-L01 CREATED 与重启（DEF-13、DEF-14，P2/P1）**
- CREATED 支持 owner/admin 取消和未启动 TTL；取消/过期/启动竞态仅一个合法迁移，占用额度恰好释放一次。
- 集中覆盖 CREATED/QUEUED/PENDING/COMPILING/RUNNING 等全部非终态；重启先回收残余执行并核对落盘，再接受业务流量。
- 建议 CREATED TTL 15 分钟；重启不可恢复非终态沿用 STALE，并记 RESTART_INTERRUPTED，保留有效统计、不自动续跑，待 DEC-02 批准。
- AC-L01：创建取消、断网/刷新不启动、TTL 和启动竞态无残留占额；逐非终态重启得到明确状态，资源及额度可验证回收。（T-L01/T-L02）

**RQ-L02 原子额度（DEF-15，P1）**
- 用户级检查/预留原子；创建落盘或 pending 注册失败回滚本次创建预留；开始执行同时持有全局及用户运行许可。start 队列满仅回滚本次启动的临时许可，保留 CREATED、pending、queued 占用及每日额度，允许原任务重试/取消/TTL 终结。
- 完成、取消、超时、异常不双释放、不泄漏；用户运行满不阻塞其他可运行用户。
- 保留现有每日按创建日期累计请求 case/估计 runtime 的计量，不改实际执行结算；取消不退还已计入每日额度。占用型许可释放不等于每日额度退款。
- 保留创建时 running 满也拒绝的既有规则，除非另经产品评审。
- AC-L02：同步竞争最后额度仅允许数量成功；全局并发大于用户限额仍遵守用户上限；创建失败正确回滚、取消不退每日额度。start 429 后原 judgeId 可重试/取消、queued 占用仍为一、无 running 许可泄漏，反复重试不重复计费。（T-L03）

**RQ-L03 权威终态（DEF-21，P2）**
- 终态持久化单一责任方、幂等；调度兜底仅填缺失，不覆盖真实 AC/WA、样本及停止原因。
- AC-L03：若干 AC/WA 后取消/超时/重复回调，实时、磁盘、清缓存及重启逐字段一致；取消与完成竞态不出现矛盾终态。（T-L04）

### 3.5 前端进度

**RQ-U01 失败与提示（DEF-16、DEF-17，P2）**
- 创建/启动/查询均检查 HTTP；启动拒绝不显示运行。401 引导登录，404 停无效轮询，429 提供重试，断网明确提示。
- 通道、启动、轮询降级独立；WS 失败回退轮询不等于任务已启动，不重复自动启动。
- 已知 judgeId 的启动/查询结果不确定时先对账；创建响应丢失且无 judgeId 时显示创建结果未知、不自动重发，可能已创建任务由 TTL 回收。本期不假设存在按请求查找任务的接口。
- Toast 在 DOM 存在后初始化；成功、校验、失败提示可见且辅助技术可感知。
- AC-U01：真实页面注入 401/404/429/断网/WS 失败，按钮及计时器正确恢复/停止/降级，重试可完成；成功与错误提示实际出现在 DOM。（T-U01/T-U02）

**RQ-U02 摘要与节流（DEF-22、N8，P2/P3）**
- 节流消息携带当前聚合快照，WS/轮询同源；终态不得被节流丢弃。
- 安全终态回收节流状态，有容量/TTL 兜底；迟到回调不能重建永久条目。
- AC-U02a：大量短任务及重复回调后条目有上界，运行节流正常、终态立即可见。（T-U03）
- AC-U02b：40 用例任务首个用例完成后能取得非空中间摘要；完成数/判定累计一致，最终与持久化一致。（T-U04）

### 3.6 回归可信度

**RQ-V01 可信回归（N5，P2）**
- 配置/测试共享输出基准；建议保留当前 10 MiB，不为旧断言降配置。超限夹具读生效额度产生“上限+增量”。
- Python 测试支持显式配置和 python3/python 探测；发布 CI 缺要求解释器必须失败，不跳过宣称通过。
- AC-V01：两断言失败及七解释器错误消除；全量零失败/错误，skip 逐项说明，关键安全及目标平台验收不跳过。（T-V01）

## 4. 非功能与运行约束

- **隔离**：trusted-local/direct 通过不能批准公网不可信代码；每个 provider 独立证明身份、文件、进程、网络和预算边界。
- **有界性**：冻结事件单行/批次/总量、输出/摘要、数字解析长度、轮询间隔、清理预算、认证容量/TTL、节流容量/TTL；非法配置启动失败。设计 §4/§6/§7 的建议数值批准前不算既定 SLA。
- **边界测试**：覆盖 limit-1/limit/limit+1，以内存、句柄、进程、条目监测证明不随历史累计线性增长；小额度隔离夹具，不在生产做资源耗尽实验。
- **可靠性**：终态、许可释放、清理幂等；清理失败留审计和重试，不虚报完成；磁盘失败不能假 AC。
- **可观测**：taskId、错误分类、无凭证关联 ID；指标不使用任意用户名/token 作无界标签。
- **兼容性**：优先保留 owner/admin、API 和状态；移除 URL 会话、弱默认配置、伪 mTLS 是有意安全不兼容，必须迁移说明。
- **性能**：空闲不热轮询，事件不重复全量读取；吞吐/RSS 预算经目标机器基准确认，不编造指标。
- **维护性**：来源解析、会话提取、比较、非终态枚举、终态提交各单一真相；不加数据库/分布式框架。
